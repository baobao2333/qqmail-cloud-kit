# 已知限制与验证记录

## 验证过的范围

原型在 Linux 云端、官方 Codex CLI **0.159.2** 验证了 OAuth DCR/PKCE、`GetMe`、`SearchMessages`、按搜索结果 `message_id` 调用 `GetMessage`，以及全新进程复用凭据。`GetMessage` 返回了 HTML 正文及 metadata；通用搜索参数入口也成功退出。这些记录不包含可发布的个人账号、邮件正文或授权 URL。

v0.1.0 在原型基础上修复默认权限、输出过滤及失败退出码，并整理成可重现源码包。发布前验证使用合成数据，不再次连接真实邮箱。原型在线成功不代表本版改动已经在线回归；当前实验 RPC、schema 和服务行为可能随版本变化。

本机离线环境的 Codex 为 0.149.1，没有用于模拟 0.159.2 在线验证。没有修改全局 CLI、现有连接或既有配置。Python 测试、平台跳过项及 CI 结果以实际运行输出为准。

发布准备时，在 Windows 原生 Python 3.14.3 运行 59 项测试，54 项通过、5 项因 POSIX 能力跳过；在已有 WSL Linux 环境补跑同一套测试，59 项全部通过、无跳过。补跑覆盖 0700/0600、FIFO、合成回调成功退出、超时及失败退出码，没有连接真实邮箱。构建回归还验证了两次生成的 ZIP 字节完全相同及文件白名单一致。

## 平台与接口

Python 3.11+，仅标准库。纯逻辑测试和打包可在 Windows 原生运行；初始化、FIFO 桥接和 app-server 辅助检查要求 POSIX。Windows 的测试跳过不代表相应运行功能通过。WSL 或其它 POSIX 主机需要单独配置与测试，不能直接套用 Windows 路径和 ACL。

`check_qqmail.py` 使用 0.159.2 的实验 app-server RPC：初始化、MCP 状态、临时 thread 和只读工具调用。其它版本未承诺兼容。参数校验只支持服务公布的基础 string/integer/number/boolean schema，复杂联合类型等会失败；单次响应上限 8 MiB、请求等待约 90 秒、搜索 limit 1..50。需要先检查 `tools`，不能假设历史字段永远相同。

桥接固定 loopback 端口 `14556`、S256 challenge 43 个 base64url 字符、state 最少 16 字符。它不是通用 OAuth 中继，不适用于任意域名、端口、scope 或公开回调地址。受限网络问题也不能仅靠桥接解决。

## 环境问题的处理

部分受管环境会同步可选插件，影响 MCP 启动；仅在遇到对应问题时，在专用配置中关闭已确认支持的可选功能。原型曾使用以下环境特定配置，普通安装不默认加入：

```toml
[features]
plugins = false
apps = false
remote_plugin = false
in_app_updates = false
```

这些开关依赖 CLI 版本和宿主环境，并非取消沙箱或系统隔离。若仍报受管策略问题，应遵循管理员权限；不要修改系统只读挂载或隔离目录。

`project_doc_max_bytes=0` 只用于本包确认为空的专用 `mail-runtime`。不要把它作为项目中跳过说明或安全规则的通用办法。脚本保留其它配置、指令和权限。

浏览器空白页曾表现为静态 JavaScript 资源没有成功返回脚本。这是该环境的资源加载现象，不能推断腾讯封锁了云端。官方 CLI 云端连接已成功；ChatGPT 自定义插件路径当时仅通过 OAuth 发现、创建阶段通用校验未成功，不能把它解释成 QQ 邮箱不支持云端，也不能宣称该插件路径已部署成功。

凭据可以刷新并跨进程复用，但撤销、到期、账号策略变化或客户端变更都可能要求重新登录。没有永久免授权保证。
