# 可选方案：官方隐藏输入与私密回调表单

先完成 [快速开始](QUICKSTART.md) 的隔离目录和固定 CLI 安装。正常网络优先官方直接回调；没有自动浏览器启动器并不等于需要 FIFO 桥接。

## 官方隐藏输入

在私有交互终端运行：

```sh
"$CODEX_BIN" mcp login qqmail \
  --scopes alias:read,mail:read \
  --oauth-client-registration dcr --no-browser
```

用户在自己的浏览器打开当前官方授权 URL 并完成授权，然后把地址栏完整回调粘贴到官方 CLI 的 `Callback URL (input hidden)` 提示中。即使回调页面未能加载，也可以使用当前完整返回地址。输入不要发到聊天、截图、命令参数或普通文件。

该行为依据 0.159.2 官方登录实现；其它版本需要重新核对。必须是真正的交互终端，终端录制、剪贴板同步和浏览器历史仍可能保留敏感信息。

## POSIX FIFO 与私密表单

当隐藏终端输入不方便且你能访问自己的 SSH 隧道时，使用本包一次性桥接。只支持 Linux/POSIX；`mkfifo`、`O_NOFOLLOW`、所有权和管道 `select` 无 Windows 原生实现。

在服务器的第一个终端执行：

```sh
python3 oauth_bridge_driver.py login
```

复制程序显示的 `RECEIVER_COMMAND` 到服务器的第二个终端执行。两个终端须设置相同的 `QQMAIL_CODEX_HOME`；第一个终端也须设置 `CODEX_BIN`。接收器取得本次 state 和 redirect 后，只绑定 `127.0.0.1:14556`。

若用户浏览器在另一台电脑，先建立快速开始中的 SSH 端口转发，再打开 `http://127.0.0.1:14556/handoff`。这个窗口属于你的 CLI，不是腾讯站点；无需输入密码、验证码或账号信息。

用户亲自完成腾讯授权后，将完整返回地址粘贴到表单隐藏输入框并提交。接收器检查 Host、Origin、CSRF nonce、state、issuer、回调目的地和参数唯一性，然后通过私有 FIFO 交给当前官方 CLI。回调不写普通文件或访问日志；官方 CLI 会另行保存 OAuth 凭据。

这里的“一次性”指有效回调最多提交一次。有效提交后跳转到不含授权码的完成页并关闭监听；提交成功不代表 OAuth 令牌交换成功，以 driver 的成功标志及退出码为准。格式或 state 不匹配的请求会被拒绝；重复有效提交会拒绝或因监听器关闭而无法连接。

两端默认等待最多 600 秒，可用 `--timeout 1..600` 缩短。超时、子进程失败和未收到有效回调均返回非零；只有本次回调已提交且官方客户端成功退出才返回 `0`。端口占用时接收器会失败，先停止自己的旧登录进程或隧道，不终止不明进程。过期后重新启动两端并使用新 URL，旧 state 和回调不可复用。

不要同时启动官方直接回调监听器和本包接收器，也不要把表单反向代理到公网。Ctrl-C 可取消操作；driver 会终止其启动的客户端并清理本次创建的 FIFO。进程被强制杀死时可能留下 `oauth-*` 私有目录，确认所属进程已停止后再由用户清理。

## 不连接邮箱的桥接演练

```sh
python3 oauth_bridge_driver.py proof
```

按输出启动接收器，并在私密表单中提交 `HARMLESS_PROOF_CALLBACK_URL`。`proof` 使用本地模拟客户端和合成 state/code，不访问 QQ 邮箱、不写 OAuth 凭据。它只能验证本地桥接，不能证明真实授权或网络可用。
